## Issues Found And Fixed

- Production `/concerts/:slug` returned `200` with a zero-byte HTML body.
  - Fixed the Pages Function asset fetch to request `index.html` by URL string and added a root fallback.
  - This directly affected direct reloads and social preview crawlers.
- Production image URLs returned the image on `GET`, but `HEAD` fell back to SPA HTML.
  - Added `HEAD` handling to `/api/image/[[key]]` so preview validators get image headers.
  - Removed the hard-coded dynamic `og:image:type` because some existing KV images have a different stored content type than their filename extension.
- Mobile drawer could appear in full-page screenshots while closed.
  - Fixed by moving the drawer fully outside the viewport when hidden.
- Edit password verification only accepted the event-specific password.
  - Fixed by allowing the admin password in verify/update/delete flows.
- Location restriction defaults did not match the requested chamber hall / 3km behavior.
  - Fixed in public settings, admin settings, and concert creation API.
- Mobile navigation hid registration behind the extra menu.
  - Fixed by promoting registration to the bottom tab bar.

## Residual Risks

- `npm install` reported existing audit issues: 8 moderate and 3 high. They were not automatically fixed because force upgrades may introduce breaking changes.
- Production admin password editing should be manually checked with the real admin password.
- Social preview caches can be sticky on LINE, X, Facebook, and chat apps. A URL may need cache refresh or a new query string after deploy.

## Photo Workflow

1. Put original photos in `private/dainagon-inbox/`
2. Run `npm run dainagon:photos`
3. Converted WebP files are written to `public/assets/prelude-cache/`
4. `src/data/dainagonPhotos.json` is updated
5. Duplicate originals are skipped and removed
6. Successfully converted originals are removed
